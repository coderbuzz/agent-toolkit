# Incident Response

## Workflow

1. Establish impact, affected users, start time, severity, and incident owner.
2. Preserve evidence and create a timestamped decision log.
3. Contain harm using the safest reversible action available.
4. Define recovery checks and monitor for recurrence.
5. Communicate verified facts, impact, mitigations, and next update time.
6. Restore service or safety, then validate data integrity and security.
7. Build a causal timeline and distinguish trigger, root cause, and amplifiers.
8. Create owned follow-up actions with tests, controls, and due dates.
9. Close only after recovery evidence and stakeholder criteria are met.

## Safety

Prioritize people, data, and containment over documentation completeness.
Require approval for destructive recovery, credential rotation with broad
impact, public communication, or irreversible data operations.
